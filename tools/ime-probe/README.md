# ime-probe — 한글이 셸에 온전히 닿는지 잰다

```sh
sh tools/ime-probe/run.sh
```

진짜 WKWebView를 세우고, 진짜 두벌식 입력기를 켜고, 물리 키코드로 「안녕」을 쳐 넣은 뒤,
**xterm이 PTY로 내보낸 바이트**를 읽어 기대값과 맞춘다. 통과하면 이렇게 나온다:

```
  ok    안녕 + space           C548 B155 0020
  ok    안녕 + Enter           C548 B155 000D
  ok    안녕 + BS 2회          C548 3134 000D
  ok    영문 hello             0068 0065 006C 006C 006F 000D
```

## 왜 이게 있나

이 판이 고친 한글 조합은 **웹뷰·입력기·xterm이 만나는 자리**에 있어서 `pnpm test`가 못 닿는다.
그 자리를 사람이 손으로 확인하면 매번 「한글을 쳐 보고 눈으로 읽는」 일이 되고, 화면에서 읽은
자모는 글꼴 폴백을 타서 **증거가 되지도 못한다**. 그래서 바이트를 잰다.

무엇이 원인이었고 무엇을 배제했는지는 `docs/ime-probe.md`에 있다.

## CI에 못 거는 이유

창을 앞으로 끌어오고 **입력 소스를 두벌식으로 바꿨다 되돌린다**. GUI 세션이 필요하고,
키 이벤트를 던지므로 터미널 앱에 손쉬운 사용 권한이 있어야 한다. 헤드리스에서는 못 돈다.

두벌식 입력 소스가 꺼져 있으면 `!! 2벌식 입력 소스를 못 찾았다`로 끝난다 —
시스템 설정 ▸ 키보드 ▸ 입력 소스에서 켤 것.

## 무엇으로 이뤄져 있나

| 파일 | 하는 일 |
|---|---|
| `run.sh` | 앱의 `terminal-ime.ts`를 번들하고, `src/index.css`의 실제 규칙을 떠 와서, 네 대본을 돌린다 |
| `probe.swift` | WKWebView + 입력 소스 전환 + 물리 키 주입. 인자: `<page.html> [키코드…] [ascii]` |
| `page.html` | 앱과 같은 옵션의 xterm 한 벌 + 앱의 조합 다리. `onData`로 나간 것을 찍는다 |

**흉내가 아니라 앱의 코드를 쓴다** — `run.sh`가 `src/`에서 모듈과 CSS 규칙을 그때그때 가져온다.
그래서 고침을 되돌리면 이 검사가 빨개진다(실측: CSS 크기를 0으로 돌리면 `3147 314F 3134 B155`,
곧 고치기 전의 `ㅇㅏㄴ녕`이 그대로 나온다).

## 대본을 늘리려면

`run.sh`의 `check` 줄을 늘린다. 키코드는 **물리 키**다(두벌식 `안녕` = `d k s s u d`):

```
d=2  k=40  s=1  u=32  space=49  return=36  backspace=51
```

기대값은 **코드포인트로 적는다.** 개행(`000D`)도 U+00A0도 눈에 안 보이는데, 이 판이 고친 것
중 하나가 「스페이스가 U+00A0으로 오던 것」이다 — 보이는 글자로 비교하면 그 회귀가 조용히
통과한다.
